# length-prefix misses by site, warm context (ABI v1 open decision 5)
#   a site is one length-prefix call site in the generated codec. Its learned
#   width is per context and starts at one byte.

  P1.2   1000 elements: no misses in the warm pass
  P2.2   500 elements: no misses in the warm pass
  P2.4   80 elements, 80 misses in one warm pass:
          80  1.00/el  loop/ListTasksDetailedResponse/tasks

# regression: a warm context must not miss on a UNIFORM payload
#   P1.2   warm misses = 0 ok
#   P2.2   warm misses = 0 ok
#   P2.3   warm misses = 0 ok
#   P2.5   warm misses = 0 ok

# `crossings` is forward + reverse: calls that leave one side's compilation unit.
# `transc` counts transcoder invocations, which are indirect calls the core makes
#   into ITSELF (ABI v1 section 4 puts every representation in the core), so they
#   are not host crossings. Counting them together is what made the drafted
#   interface look like 15,137 calls on a 1,000-row response.
# `prefix` counts length-placeholder resizes: ABI v1 open decision 5. `enc cold`
#   is a context whose learned widths have never been set, `enc warm` the steady
#   state. P2.4 alternates element bodies across a varint length boundary by
#   construction, so a per-site learned width is wrong on every element of it:
#   that row is the one decision 5 turns on.
# M1's element type is a LEAF, so its rows batch. M2's is not (ABI v1 7.2), so
#   M2 costs two calls per element plus one run per repeated field it carries.
