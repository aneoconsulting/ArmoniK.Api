## Core services at a glance

Every client-facing service below is defined once in `Protos/V1/` and re-generated for each language — the request
and response shapes and field docs are identical across C#, Python, C++ and Angular; only the calling convention
differs. See the [glossary](../concepts/glossary.md) for what each concept means.

| Service | Purpose |
|---|---|
| `Sessions` | Create and manage submission contexts (default task options, allowed partitions). |
| `Tasks` | Submit tasks, list/filter them, check status, cancel them. |
| `Results` | Create result placeholders or results with data, upload/download data, look up owning tasks. |
| `Partitions` | List available compute partitions and their configuration. |
| `Versions` | Report the control plane and API versions — see the [Quickstart](../getting-started/quickstart.md). |
| `Events` | Stream task/result changes instead of polling. |
| `Agent` / `Worker` | Worker-facing services, relevant only when implementing a compute-side worker. |

```{note}
`Submitter` also appears in the proto reference but every RPC in it is deprecated — use the services above instead.
```

Find the exact method signature, parameters and error behavior for any of these in the per-language reference
linked above, or follow [Submit a task and retrieve its result](../concepts/submit-and-retrieve-results.md) for a
worked example using `Sessions`, `Tasks` and `Results` together.
